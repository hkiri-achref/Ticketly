# F-02 — Venues CRUD

## What was built
The first real vertical slice of catalog-service: `Venue` JPA entity with an
`Address` embeddable **record**, Flyway `V2__venues.sql`, `VenueRepository`,
`VenueService`, `VenueController` (POST 201+Location, GET by id, paged
case-insensitive city search), and an `ApiExceptionHandler` returning RFC-7807
`ProblemDetail` (400 with `errors[]`, 404).

## Concepts practiced
- **Entity vs record (§6)**: `Venue` is a class (protected no-arg ctor for
  Hibernate, ID-only equals/hashCode, no setters); `Address` is a record because
  an address is a value — equal components mean the same address.
- **`@Embeddable` record + `@Embedded`**: one Java field → three columns of the
  owning table (Hibernate 6.2+). Proven by a `@DataJpaTest` asserting the raw
  columns via `JdbcTemplate`.
- **Derived queries into embeddables**: `findByAddressCityIgnoreCase` walks the
  `address.city` path; `IgnoreCase` compiles to `upper(city) = upper(?)`, so
  the migration's functional index uses `upper()` too — index expressions must
  match what the ORM actually emits.
- **Validation on record components** + compact constructor normalization
  (null-safe `strip()` so validation, not an NPE, reports missing fields).
- **`ProblemDetail`** with `setProperty("errors", …)` extension members.
- **Stable pagination contract**: `@EnableSpringDataWebSupport(VIA_DTO)`
  serializes `Page` as `PagedModel` (`content[]` + `page{}`).
- **Slice tests**: `@DataJpaTest` on real Postgres via `@ServiceConnection`
  (proves migration ↔ entity agreement), `@WebMvcTest` + `@MockitoBean`
  (millisecond web tests). Boot 4.1 moved these annotations to per-module
  packages; `TestEntityManager` is gone — plain `EntityManager` works.

## Interview questions I can now answer
1. *Why can't a JPA entity be a record, and where do records belong instead?*
   Records lack a no-arg ctor, are immutable and final, and have value-based
   equality — Hibernate needs to instantiate empty, mutate, proxy, and track
   identity. Records shine as DTOs, embeddable value objects, projections,
   events, and config.
2. *How do you return RFC-7807 errors and keep paginated JSON stable in
   Spring?* `@RestControllerAdvice` methods returning `ProblemDetail`
   (extensions via `setProperty`); `pageSerializationMode = VIA_DTO` so the
   page shape is the documented `PagedModel`, not `PageImpl` internals.

## Production concern deliberately simplified
No authentication/authorization — anyone can create venues until F-06/F-07
(resource server + roles). Also: duplicate venues are allowed (no natural-key
constraint), and there is no update/delete flow yet, so data hygiene relies on
the check constraint and validation alone.
